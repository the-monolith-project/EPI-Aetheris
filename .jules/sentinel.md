## 2026-08-08 - Fix hardcoded credentials and exception information leakage
**Vulnerability:** The database health check endpoint in `backend/api/main.py` had default fallback credentials (`aetheris_user`, `aetheris_secure_password`) hardcoded directly in the source code. Furthermore, a failure to connect returned the internal exception message (`str(e)`) to the client.
**Learning:** Default fallbacks for environment variables that store credentials create a risk of accidental inclusion in public repositories or deployment of systems with easily guessable default credentials. Unhandled exception exposure in an API leaks backend state and technology stacks.
**Prevention:** Always require sensitive environment variables to be set externally (or let connection libraries handle their absence naturally by failing). Return generic error messages on HTTP 500 status codes instead of the raw trace or exception string.
## 2024-02-14 - Fix Path Traversal Vulnerability in PDF Downloader
**Vulnerability:** The `_clean_filename` function in `backend/ingestion/minsal_common.py` unquoted URL components but failed to strip out directory traversal characters (`../` or `%2E%2E%2F`). This meant that a malicious PDF link could cause the downloaded file to be written outside the intended destination directory (e.g., overwriting sensitive files on the file system).
**Learning:** URL decoding (`urllib.parse.unquote`) inherently introduces path traversal risks if the resulting string is used directly in file system operations. Since URLs often obfuscate path traversal characters (like `%2E%2E%2F`), decoding must always be followed by robust sanitization of the file path.
**Prevention:** Always extract only the base filename using path manipulation libraries (e.g., `Path(name).name`) after URL decoding, and never construct raw paths by concatenating unsanitized strings directly.
